# Three Bases inspiration library — how to search

The library is `three-bases-library.sqlite`, with helpers in `lib/query.py`. It holds mechanics from other games for designing Three Bases (rules: summary.txt in the project). Only mechanics are reused, never names or wording. Never present a link or count from the database as more than it is: links made by `text_pattern` are automatic and can be wrong; `claude_review` and `via_keyword` are more reliable.

## Model in one paragraph
`entities` holds everything playable (units, spells, items, relics, terrain, bosses, events, modifiers, game rules) and every game keyword (`category='keyword'`, with its definition as text). `entity_links` connects entities: `has_keyword`, `grants_keyword`, `mentions_keyword`, `variant_of`, and later `summons`, `transforms_into`, `references`. `concepts` is Claude's own cross-game network, grouped in facets (effect, combat, trigger, condition, cost, resource, structure, role, scope, problem); a concept can have several parents (`concept_parents`), and the view `concept_tree(root, id)` gives every descendant. `entity_concepts` links entities to concepts with a role: does, grants, benefits, counters, cost, exhibits (design problems). `concept_relations` holds synergizes / counters / mitigates / enables / variant_of / tension between concepts — Claude's analysis, not source data. `factions` stores a concept profile per faction (share of the faction's entities, and lift vs the game average).

## Links between entities (second pass)
`references`, `summons`, `generates` and `transforms_into` connect an entity to another entity of the same game that its text names (e.g. a card that summons a named token). `equivalent_keyword` connects keywords of different games whose reviewed concept sets are identical (e.g. Hearthstone Taunt, Shadowverse Ward, Gwent Defender) — use it to jump from one game's version of a mechanic to the others. Card names inside rules text are masked as NAMEDCARD before pattern tagging, so a name like "Undying Resolve" no longer creates false tags.

## Card-to-card interactions
Entities of category `tribe` are card types/tribes per game (Beast, Dragon, Machina, Zombie…): `has_type` links cards that are that type, `cares_about_type` links cards whose text cares about it. Together with keyword links (`has_keyword` / `grants_keyword` / `mentions_keyword`), name links (`references`, `summons`, `generates`, `transforms_into`) and role-tagged concepts (does / benefits / cost), this lets you recover interactions: `interactions <card>` lists partners by direct link, shared type, keyword and concept roles (including concept relations such as sacrifice → enables → death payoffs); `combo <cardA> <cardB>` explains every known connection between two cards.

## Hierarchy
Top-level roots: effect, combat, trigger, condition, economy (resources and costs), scope, structure, win_condition, role, design_problem. A concept can sit under several parents; queries on a parent include all descendants.

## Commands
`python3 lib/query.py games` · `interactions "<card>" [game=x]` · `combo "<card A>" "<card B>" [game=x]` · `concepts <term>` · `concept <id> [per_game=4] [role=does] [game=x]` · `cooccur <id> [game=x]` · `search "<fts query>" [game=x]` · `entity "<name>" [game=x]` · `faction <game> [name]` · `problem <p_id>`. Direct SQL is fine for anything else.

## How to answer the typical questions
"Ideas for a faction that …": translate the description into 3–6 concepts; run `concept` on each and `faction` on every game to find factions whose profile matches; read those factions' keywords and top entities; look for how each game builds the identity (resource, positional rules, triggers), not just which effects it uses.

"I'm not happy with this mechanic, suggest alternatives": identify the mechanic's concept(s); look at siblings under the same parents, at `variant_of` relations, and at how each game implements the same role with a different trigger, cost or scope. Present alternatives as differences in trigger/cost/condition/scope.

"Cards that work well with X": find X's concepts; use roles — entities that `benefits` from X, that `grants` X, plus `concept_relations` synergizes/enables; check `cooccur` for combinations games actually print.

"The game has this issue": map the issue to a `p_*` problem concept (`concepts p_`), run `problem`, then pull concrete examples for each mitigating mechanic from several games. If no problem concept fits, say so and work from mechanics directly.

## Rules for reading results
Always break results down per game and read each game's own keywords and wording for the concept before generalising; a concept usually looks different in each game, and those differences are the useful part. Never conclude from the largest game alone (Magic has far more entries than the rest); a game with three relevant entries can hold the most original idea. Check the role, not just the concept: "does heal", "benefits from heal" and "counters heal" are different design spaces. Mention when a game has nothing for a concept — absence is information too. When the answer depends on links made by `text_pattern`, spot-check the actual text before relying on it.

## Tagging quality by source
Most precise: games whose keywords come from official glossaries and explicit keyword fields (Runeterra, Gwent, Duelyst, Slay the Spire, Into the Breach, Blood Bowl). Keyword links marked `claude_inference` (Faeria, Hearthstone, Battlegrounds, Shadowverse, Underworlds) rest on Claude's knowledge, not source definitions. Noisiest: long prose (D&D) and Warhammer ability text, where text patterns over-tag; always read the text there. Darkest Dungeon text is rendered by Claude from raw data fields.

## Keyword definitions
Where a source had no glossary, keyword definitions were verified online in the second pass and stored as the keyword's text (paraphrased): Hearthstone and Battlegrounds from hearthstone.wiki.gg, Faeria from faeria.com's keyword rulings, Shadowverse Skybound Art from shadowverse.com; new Magic keywords from the cards' own oracle text. A few remain Claude inferences from card text (Shadowverse Maneuver, Underworlds Hunter and Innate) and say so in their source_type.

## Link reliability, most to least trusted
`claude_review` (keyword or entry mapped by hand from its definition) > `via_keyword` (inherited from a reviewed keyword) > `claude_inference` (keyword mapped from Claude's knowledge because the source has no definition) > `data_rule` / `game_structure` (rule applied to a whole category) > `text_pattern` (automatic). Pattern quality differs by source: short card text (Hearthstone, Runeterra, Shadowverse, Gwent, Faeria, Duelyst, Magic, Underworlds) is good; long prose (D&D, Warhammer army rules, wiki-based Inscryption/Into the Breach prose) is noisier; Darkest Dungeon text is rendered by Claude from raw fields.

## Size skew
Magic (~19,800 entries), Hearthstone (~5,700), 40k (~4,400), Shadowverse (~3,800) and Age of Sigmar (~3,600) dominate raw counts. Compare games by share of their own entries, and always read the small games (Inscryption, Into the Breach, Darkest Dungeon, Blood Bowl, Faeria) for any concept they have.

## Games
- `darkest_dungeon` — Darkest Dungeon (1068 entries). Skill and item text is rendered by Claude from raw data fields (ranks, effects, buffs), not official tooltips; effect and buff names resolved through Effects.txt and JsonBuffs. Highest skill level kept; monster tiers A-D merged (first tier kept). Glossary from Misc.xml localization.
- `duelyst` — Duelyst (837 entries). Keyword definitions come from modifiers.json (*_def). Card-specific modifier names were not loaded as keywords. Bloodbound Spells (General signature spells) are hidden spells in the data and are kept.
- `dnd5e` — Dungeons & Dragons 5e (SRD) (1566 entries). Where an entry exists in both editions, the 2024 version is kept. Damage types not loaded as keywords (every attack would link to them). Mundane equipment, backgrounds, languages, alignments, skills, ability scores and level tables dropped. Monsters with only plain attacks dropped; same-template monsters merged.
- `faeria` — Faeria (465 entries). Source has no keyword glossary. Keyword concept links are Claude inferences from the keyword names and how cards use them (method claude_inference); Corrupt and Divine are left unmapped because their exact rules are not in the data.
- `gwent` — Gwent (standalone) (1347 entries). Keyword definitions from the cards themselves (14.8), supplemented with 2020 definitions for terms still used in 14.8 text. NonOwnable set (tokens) dropped.
- `hearthstone` — Hearthstone (5663 entries). No keyword glossary in the source. Keyword entities come from bold terms in card text; their concept links are Claude inferences (claude_inference). Prepare, Fabled, Shatter, Gigantify and Bonus Effect left unmapped: their rules are not in the data and Claude is not certain of them. Reprints (Core/Legacy/Vanilla) were merged by name.
- `hs_battlegrounds` — Hearthstone Battlegrounds (2346 entries). No keyword glossary in source; keyword concept links are Claude inferences. Unmapped: Rally, Activate, Pass, Deity, Buddy, Timewarp, Bonus Keyword, Bounty. Golden/upgrade tiers and ability levels merged: one entry per name and text.
- `inscryption` — Inscryption (406 entries). Cards carry no rules text of their own; their mechanics come from sigils (keywords), traits and special behaviours. Prose descriptions stored in extra.description, not tagged.
- `into_the_breach` — Into the Breach (336 entries). Unit and weapon text is assembled by Claude from wiki infobox fields and skill templates plus the Description section; strategy, trivia and lore sections dropped. Keyword definitions from the wiki's abilities/status page and special templates.
- `runeterra` — Legends of Runeterra (1932 entries). Keyword definitions from the official glossary (globals). Champion level-up text appended to the card text. Path of Champions dropped by agreement except its items (category item, edition "Path of Champions"); in that mode items are attached to cards.
- `mtg` — Magic: The Gathering (20393 entries). Cut before loading: tokens/emblems/art cards and other non-playable entries, cards with no text, joke sets, all commons (by latest printing, so slightly imprecise), keyword-only creatures, non-creature lands, multiplayer-only cards, exact duplicates. Cut here: mana-only cards (mana rocks and mana dorks) and cards identical apart from numbers, colours, mana symbols, basic land types and creature types. Keyword definitions taken from reminder text printed on the cards where available; mapping by Claude.
- `shadowverse` — Shadowverse (3841 entries). No keyword glossary in the source; keyword concept links are Claude inferences. Unmapped: Skybound Art, Super Skybound Art, Maneuver, Insight. Craft numbers mapped to names by Claude (0 Neutral, 1 Forest, 2 Sword, 3 Rune, 4 Dragon, 5 Shadow, 6 Blood, 7 Haven, 8 Portal). Tokens (set 90000) and alternate-art duplicates dropped. Evolved text appended as "Evolved:".
- `sts1` — Slay the Spire (909 entries). Keyword definitions from keywords.json. Event choices kept, event prose dropped. Monster text built from move data (intent, damage, block).
- `sts2` — Slay the Spire 2 (Early Access) (1362 entries). Early Access data (version in changelog: 0.107.1, 2026-06-18). The [S] icon in text is read as "star" (Claude inference: the Regent's Stars resource). Keyword definitions from keywords.json (7) — the many other mechanics are in powers (status category). Monster text built from move patterns.
- `wh_40k_10e` — Warhammer 40,000 (10th edition) (4397 entries). Rules referenced by units (weapon and unit special rules) are keywords; their concept links come from text patterns on their definitions (not hand-reviewed except the most used ones). Faction-level rules are game_rule entries. Units without any ability or special rule dropped. Text markup cleaned.
- `wh_aos_4th` — Warhammer Age of Sigmar (4th edition) (3583 entries). Rules referenced by units (weapon and unit special rules) are keywords; their concept links come from text patterns on their definitions (not hand-reviewed except the most used ones). Faction-level rules are game_rule entries. Units without any ability or special rule dropped. Text markup cleaned.
- `wh_bloodbowl3` — Blood Bowl (Third Season) (358 entries). Rules referenced by units (weapon and unit special rules) are keywords; their concept links come from text patterns on their definitions (not hand-reviewed except the most used ones). Faction-level rules are game_rule entries. Units without any ability or special rule dropped. Text markup cleaned.
- `wh_killteam` — Warhammer 40,000: Kill Team (2346 entries). Rules referenced by units (weapon and unit special rules) are keywords; their concept links come from text patterns on their definitions (not hand-reviewed except the most used ones). Faction-level rules are game_rule entries. Units without any ability or special rule dropped. Text markup cleaned.
- `wh_underworlds` — Warhammer Underworlds (3198 entries). Fighter cards are not in the data, only objective, ploy, upgrade and spell cards. No keyword glossary: keyword links are Claude inferences; Hunter and Innate left unmapped. Duplicate reprints merged.

Dropped by agreement and not in the library: Kingdom Death: Monster, Darkest Dungeon 2 and DD1 DLC, Hearthstone Mercenaries, Path of Champions (except items), Warhammer 40k 9th/7th/2nd, Horus Heresy, Legions Imperialis, Apocalypse, Epic Armageddon, Adeptus Titanicus, Aeronautica Imperialis, Battlefleet Gothic, old Age of Sigmar, old Blood Bowl, Necromunda, Mordheim, Warcry, Warhammer Fantasy, Middle-earth SBG, Warhammer: The Old World.
