# Three Bases inspiration library — how to search

The library is `three-bases-library.sqlite`, queried with `python3 library/tools/query.py <command>`. It holds mechanics from other games for designing Three Bases (rules: summary.txt in the project). Only mechanics are reused, never names or wording. Never present a link or count as more than it is: automatic tags can be wrong.

## Model
`entities`: every card, unit, spell, item, location, ability, rule, keyword (definition as text) and tribe (card type). `concepts`: Claude's cross-game network, sorted by outcome first and mechanism second; a concept can have several parents, and a query on a parent includes all its descendants (`concept_tree`). So `concept no_damage_output` finds Hearthstone Freeze (attack_lock), Runeterra Frostbite (attack_zero) and damage prevention together, and `concept suppress` adds can't block, immobilize, silence and total disable. Effects sit under who they help or hurt (`helps_me`, `hurts_enemy`, `drawback`, `game_rules`); `buff` is any way a unit gets stronger (stat gain is `stat_gain`) and `debuff` any way it gets weaker (stat loss is `stat_loss`); "this turn / round only" is the separate marker `temporary_effect`. The tree is in `CONCEPT_TREE.md`. `entity_concepts`: entry → concept with a role: does, grants, benefits, counters, cost, exhibits (design problems). `concept_relations`: synergizes, enables, counters, mitigates, tension, variant_of between concepts (Claude's analysis). `entity_links`: keyword links (has, grants, mentions, describes), type links (has_type, cares_about_type), name links (references, summons, generates, transforms_into), variant_of, equivalent_keyword (the same keyword in another game; for jumping between games only). `trigger_effect`: "when X, do Y" pairs with a frequency limit; a clause starting "via keyword K:" comes from the entry's keyword. `faction_signature`: signature mechanics, keyword signatures (`kw:<keyword>`) and splash per source faction. `concept_precision`: how often the current automatic tags are right per concept and game. `mechanic_repeat`: entries that repeat an earlier entry's mechanic in the same game (same category, concepts and trigger pairs). `factions` / `faction_archetypes`: concept profiles and archetypes per faction (share of the faction, lift over the game average).

## Commands
- `concepts <term>`: find concept ids.
- `concept <id> [per_game=4] [role=does] [game=x] [distinct=1]`: entries for a concept, per game; warns where its automatic tags are often wrong; distinct=1 skips repeats of a mechanic.
- `cooccur <id> [game=x]`: concepts printed together with it on cards, as the share of its entries per game averaged over games (each game counts equally).
- `problem <p_id>`: mechanics that ease or worsen a design problem, with examples.
- `faction <game> [name]`, `archetypes [id] [game=x]`: faction profiles and archetypes.
- `signature <game> [faction]`: each faction's signature mechanics with example cards, its own keywords, and the other factions' mechanics it splashes.
- `splash <concept> [game=x]`: who owns a mechanic, and which other factions use it on a few cards, with the splashing faction's own signatures on each card (how the splash fits that faction).
- `grid [trigger] [effect] [game=x] [freq=bound]`, `unused_pairs <trigger>`: the trigger × effect design space and its gaps.
- `frequency [bound] [trigger=x] [effect=x] [game=x]`: pairs by frequency limit, as shares per game averaged over games (each game counts equally): per_card (spell, Place/on-play, own death, once per game), per_round (once-per-turn cap, own turn start/end, attack, kill, tap), unbounded (other units' or repeated events), static (aura). The basis column says why. Use it for the frequency check: card advantage and resources must be bounded unless they are the faction's signature.
- `interactions "<card>" [game=x]`: a card's partners by link, type, keyword and concept role.
- `combo "<A>" "<B>" [game=x]`: every connection between two cards, by layer: link, engine (an effect of A sets off a trigger of B: summoning sets off "an ally is played", destroying or sacrificing sets off "a unit dies", damage sets off "takes damage", an immediate attack sets off attack effects, a spell sets off spell triggers), role (A does or pays what B benefits from), role_tree, keyword, type, relation.
- `search "<fts query>" [game=x] [per_game=4] [distinct=1]`: full-text search, at most per_game hits per game; `entity "<name>" [game=x]`, `games`.
- A merged name still resolves: the commands say which entry kept it. Created cards have edition `non-collectible`. A Slay the Spire upgrade that changes the mechanic is `<name>+` (variant_of the base card); one that changes only numbers is in the base card's `extra.upgraded_text`. Direct SQL is fine for anything else.
- Checks after any change: `tools/regression.py <db> check`, `tools/combo_check.py <db>`, `tools/trigger_pairs.py <db> check`, `tools/test_query.py <db>`.

## Typical questions
"Ideas for a faction that …": translate the idea into 3–6 concepts; run `concept` on each and `signature` / `faction` on the games whose factions match; read those factions' keywords and top cards; look at how each game builds the identity (resource, positional rules, triggers), not only which effects it uses.

"Alternatives to this mechanic": find its concepts; look at siblings under the same parents, variant_of relations, and how other games reach the same role with a different trigger, cost or scope.

"Cards that work with X": entries that benefit from X or grant it, concept relations synergizes/enables, `cooccur`, and `combo` to check a pair.

"The game has this issue": map it to a `p_*` concept (`concepts p_`), run `problem`, pull examples of each mitigating mechanic from several games. If none fits, say so.

## Reading results efficiently
- One or two targeted commands per question; never dump tables.
- Results come per game with a cap per game; compare games by share of their own entries, never by totals. Magic (about 18,900 entries) and Hearthstone (8,100) would otherwise drown out Inscryption, Into the Breach, Blood Bowl, Faeria or Marvel Snap, which often hold the most original ideas. Say when a game has nothing for a concept.
- Read each game's own wording for a concept before generalising; the differences between games are the useful part.
- Check the role: "does heal", "benefits from heal" and "counters heal" are different design spaces.
- Before relying on an automatic tag, print the text of the two or three cards the answer rests on (a few lines).

## Reliability
Link methods, most to least trusted: `claude_review` (read by hand) > `via_keyword` (inherited from a reviewed keyword) > `via_link` (inherited from a card it names) > `claude_inference` (keyword mapped from Claude's knowledge, no source definition) > `data_rule` / `game_structure` (rule for a whole category) > `engine_rule` / `text_pattern` (automatic wording rules). Short card text (Hearthstone, Runeterra, Shadowverse, Gwent, Faeria, Duelyst, Magic, Snap, Underworlds) tags well; long prose (Warhammer army rules, Inscryption and Into the Breach wiki text) is noisier. Keyword definitions from Claude's inference say so in source_type (Faeria, Hearthstone, Battlegrounds, Shadowverse, Underworlds, Marvel Snap). Darkest Dungeon text was built by Claude from raw data fields; Underworlds upgrades loaded on 12 Oct 2026 get items_consumables (and damage/ranged from their attack profile) as data_rule; `describes` keyword links are Claude's reading of the keyword's definition; Underworlds warscroll abilities are Claude's paraphrase of the official PDFs.

## What the tags mean in each game
- Everywhere: put a card from your deck into your hand = tutor or draw; put a new card into your hand = generate_cards; "discard pile" is not discard; "N% chance" is random, a plain percentage is not.
- Kill Team, 40k, Age of Sigmar, Blood Bowl: a faction is an army; Age of Sigmar armies of renown and Legends lists are in extra.army_of_renown / extra.legends. 40k "Bodyguard unit" is the unit a Leader is attached to (not bodyguard). Age of Sigmar abilities without a Timing line are passive. A unit being activated = turn_start; real action abilities (1AP, Timing:, Special Action) = activated. Re-rolls = advantage; only D6 and random-number rolls are random_effect. Invulnerable saves, Feel No Pain, Ward and "-1 to hit for attacks that target this unit" = damage_reduction; debuff needs an enemy target. Objectives and control scores = zone_control; engagement range, combat range and tackle zones = zone_of_control. Once per battle = once_per_game; once per turn/turning point/phase = cooldowns. Blood Bowl: Block/Blitz/Foul are combat (not blocking); "player" means a piece on the pitch.
- Underworlds: "out of action" = destroy; upgrades = items_consumables; Inspired = upgrade; removing wound tokens = heal; "cannot be driven back" = immunity; feature tokens and lethal hexes = terrain.
- Slay the Spire 1–2: Curse = junk_cards (not debuff); self "Lose N HP" = life_payment. Monster moves = telegraphed_threats; relics = items_consumables + passive. STS2 Stars = multiple_resources; Osty = summon:benefits; co-op cards = team_play.
- Darkest Dungeon: a hero's own minus stats = drawback, minus stats on enemies = debuff. Trinkets = items_consumables; quirks, diseases, afflictions and virtues = traits_quirks. Stress = stress_morale; bleed/blight = damage_over_time, cures and resistances = damage_over_time:counters. "vs beast/eldritch/man/unholy" = tribal.
- Magic: patterns read the text without reminder text (the keyword brings its own concepts) and with the card's own name as "name". Keyword links: has = Scryfall's keyword list (abilities and keyword actions such as scry or fight) or a keyword the card gives itself; grants = given to other objects, including tokens it creates ("creatures you control have flying", "create a 1/1 Spirit with flying"); mentions = only named ("creatures with flying"). Lands are mana, not terrain. A token a card makes is linked by generates. Bounce = return_to_hand; tuck (top or bottom of the library) = removal + deck_position; tapping enemies or "doesn't untap" = disable; own "enters tapped" = drawback; colour change = type_grant; "deals combat damage to a player" is an on_attack trigger.
- Hearthstone: Freeze = attack_lock + temporary_effect (the frozen character misses its next attack), not a total disable. Battlegrounds: Freeze keeps the tavern's offers (selection); team_play covers Duos passing and teammates. Shadowverse: Ward = taunt, not shield.
- Lorcana: "banish" = destroy (the card goes to the discard pile), banishing your own card = sacrifice, an item or character that banishes itself for its ability = self_destruct. Evasive and Ward = immunity (cannot be challenged / chosen), Alert = immunity:counters, Bodyguard = taunt, Shift = upgrade + cost_type, songs and Singer = cost_type. Exerting an opposing character = disable, ready = untap, putting a card into your inkwell = resource_gain, into the opponent's inkwell = removal; gaining or losing lore = points_scoring; locations and "while here" = zone_control. Ability names are in extra.ability_names, not the text.
- Stormbound: numbers that change by card level are written as five values ("2/3/4/5/6"). Bordering and surrounding = adjacency; freeze = disable; poison = damage_over_time; vitalize = permanent_growth; confuse = forced_movement; "disable the ability" = silence; convert = steal; damage to the enemy base = direct_damage, to your own base = life_payment.
- Star Wars Unlimited: "defeat" = destroy (your own unit = sacrifice), exhausting an enemy = disable, ready = untap, capture = removal, an Upgrade = merge_attach, experience tokens = stat_gain, a card put into play as a resource = resource_gain, damage to a base = direct_damage, "use the Force" = coin_economy. Sentinel = taunt, Shielded = shield, Hidden = immunity for the phase, Ambush = attack_now. Text from the English localisation; keyword and trait names translated from the French export.
- The Elder Scrolls: Legends: two lanes (field, shadow); "in this lane" and the lane names = lane_identity, runes broken = direct_damage, more magicka = resource_gain, items = merge_attach. Guard = taunt, Ward = shield, Cover = immunity for a turn, Lethal = deathtouch, Slay = on_kill, Summon = on_play, Last Gasp = death_trigger. Keyword definitions are Claude's summaries.
- Into the Breach: Smoke and being submerged = attack_lock, Webbed = immobilize, Frozen = total disable. Duelyst Provoke and Faeria Taunt = taunt + immobilize.
- Marvel Snap: locations are terrain + lane_rule; cross_lane, lane_identity, lane_closure and forced_placement describe lane play.
- Text layout: a Runeterra champion is its level 1 card (with its level-up condition) plus its levelled side, "<name> (level 2)", linked by transforms_into; Shadowverse "Evolved:" text is appended to the card; Shadowverse crafts are named (Forest, Sword, Rune, Dragon, Shadow, Blood, Haven, Portal, Neutral).
